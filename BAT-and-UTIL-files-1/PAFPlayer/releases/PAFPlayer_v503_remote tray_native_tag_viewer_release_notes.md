# PAFPlayer V503 — household tray clients and native tag viewer

- The official tray's **Open tag viewer** item launches a separate native Windows window with Overview, Tags, Lyrics, Artwork and Technical tabs. It shows the current file's readable tags, selected lyrics, artwork previews, file facts, and FFprobe container, stream and chapter data. It follows track/artwork changes and has Refresh.
- `PAFPlayer --tray-only machineservername:666` runs a tray client on another Windows computer. It starts no playback, does not claim the server's official single-instance mutex, and never replaces its icon. Each client is labeled with its target server and connection state.
- A separate named Windows mutex permits one tray-only icon per target in each logon session. A heartbeat verifies that the target is the official PAFPlayer V503 or newer owner, reports disconnects, and reconnects after server restarts. Every remote playback request includes the currently verified owner identity; the server rejects stale ownership and uses its existing action queue.
- The remote tray retains triple-left previous, triple-right next, double-click Play/Pause, and delayed single-right menu behavior. Its menu offers playback, web configuration, native tag viewer, server/version, and **Exit this tray**. Exiting a remote tray does not exit the server.
- The click sequence uses monotonic timestamps and the Windows double-click interval, clamped to 350–900 ms. A double-click toggles Play/Pause only after the window expires; a triple-click takes precedence. A single right-click opens the menu after the same delay, and a triple-right-click suppresses it.
- The official player's tray is enabled by default through the saved global `TrayIconEnabled` setting. Its web configuration has a **Windows tray icon** enable/disable control. `--tray` and `--no-tray` override that preference for the current run without rewriting it. `--instance` keeps additional playback processes separate from the official tray owner; normal second launches continue to use the existing local handoff.
- When the official process exits, an eligible explicit instance may win the existing named mutex and take over the official tray. Remote clients recheck the official owner identity and reject stale commands while reconnecting. Normal shutdown removes the icon; after a crash, Windows or Explorer may briefly retain a stale display.
- The playing computer must explicitly bind its web server to a LAN address, for example `--web-host=0.0.0.0 --web-port=666`, and permit that port through the Windows firewall. The viewer uses read-only detail/artwork endpoints. The existing LAN controls use plain HTTP without pairing, so the port should be limited to a trusted network.
- The Windows 10 lock-screen documentation now reflects the current experimental SMTC bridge: title/artist/album, artwork, playback state and timeline can be published, but Windows chooses whether to show the card. The current bridge has no lyric publication control and cannot place the native viewer on the secure lock screen.
